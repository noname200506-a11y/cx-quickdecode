# CX 快速解码（桌面悬浮 · 快捷图片解混淆）

> **仓库说明**：本仓库只含源码、文档与样例图；编译产物（`*.exe`）不入库，
> 用 `bash build.sh publish` 现场生成（依赖 .NET 8 SDK + NuGet 上的 `Svg` 包，见 `NOTICE.md`）。
> 自检向量需要 cx-E2EE 那份 Python 参考实现（`cx_core.py`），生成命令也在 `NOTICE.md` 里。

把 **cx-E2EE 网页端「图片区域打码」** 的还原流程做成一个常驻桌面的小悬浮窗：
预输入密码 → 剪贴板 / 截图 / 拖入文件，三步就出图，结果自动复制到剪贴板。

- 算法层是 `src/image-crypto.js`（V3 区域打码）的 **C# 逐字节等价移植**，并用 Python/JS 参考向量做过对照（见「自检」）。
- 只用 .NET 8 + WinForms + 自写 PNG 编解码：不联网、不写注册表、不装服务，配置就在 exe 旁边。

---

## 一、怎么用

| 你要做的事 | 操作 |
|---|---|
| 解码剪贴板里的第一张图 | 点 **剪贴板解码** / `Ctrl+Alt+Q` / 在密码框里按回车 |
| 框选屏幕上的打码图解码 | 点 **截图解码** / `Ctrl+Alt+S`，拖出矩形 |
| 解码本地图片 | 点 **打开图片** / `Ctrl+Alt+O`，或**把图片直接拖进窗口** |

1. 先把密码填进悬浮窗的密码框（会自动记住；右上「显示」可临时看清）。
2. 解码成功：窗口左下出现缩略图、状态栏变绿、图片**自动进剪贴板**；点缩略图/状态栏看大图（可另存为、复制、1:1/适应）。
3. 解码失败：状态栏变红并说明原因（最常见是「密码不对」或「这张图没有元数据」）。

悬浮窗：拖标题条移动 · `–` 折叠成一条 · `✕` 收进托盘（双击托盘图标再打开）。
右键托盘图标还有：记住密码、窗口置顶、空闲自动降耗、退出。

## 二、它到底解的是什么

cx-E2EE（C-X 安全终端）网页端的 V3 打码：

1. 把选定区域按 `unit`（PNG 路径 = 8px）切成小块，用密码派生的 seed 做 **块级置换**；
2. 每块再叠一组同源扰动（亮度偏移 ±40、U/V 取反、U/V 互换），RGB→YUV 后压亮度域；
3. 输出时四周外扩 **8px 边框**，把「区域表 + 签名（含密码）」写进边框像素的 **R 通道最低位**（LSB）；
4. 还原只需 **这张图 + 密码**：读边框 LSB → 用密码重算签名比对（不符就是密码错）→ 逆置换/逆扰动 → 裁掉边框。

本工具做的就是第 4 步，另外两条兜底：

- 图上没有元数据（截图 / 剪贴板位图 / JPEG 重压过）→ 用你框的区域（或整图）解，并**自动在 unit=8/16 × soft=0/1 × 块网格偏移 里挑「块缝最平」的那组**（状态栏会写它选了什么）。
- 打开的是普通图片（不是打码图）→ 会说「未识别到打码元数据」。

## 三、轻量与便携

| 项 | 数值 / 做法 |
|---|---|
| 体积 | 免运行时版 **63 MB**（单文件，任何 Win10/11 x64 双击可用）；轻版 **231 KB**（要求本机有 .NET 8 Desktop Runtime） |
| 常驻内存 | 约 55–60 MB 工作集；空闲降耗后会被 `EmptyWorkingSet` 压回去 |
| 空闲 CPU | **0%**：没有任何定时刷新的动画；空闲后连 1 秒一次的检查定时器都会停掉 |
| 空闲降耗 | 无操作 `IdleSeconds`（默认 20s）后：进程优先级降到 **Idle** → `GC.Collect` → `EmptyWorkingSet` 收缩工作集 → 停掉定时器；鼠标进入窗口 / 点按钮 / 按热键立即恢复 Normal |
| 解码耗时 | 元数据路径 1280×800 约 **17 ms**；无元数据自动择优（4 组合 + 最多 unit² 次偏移搜索）约 **0.5 s** |
| 便携 | 单 exe；配置写在 exe 同目录 `cxq.config.json`（目录不可写才退回 `%APPDATA%\CxQuickDecode\`），拷走整个文件夹即搬家 |

> 密码保存在配置里用 Base64+XOR 轻混淆（防肩窥，**不是加密**）；不想落盘就把托盘菜单里的「记住密码」取消。

## 四、命令行（给批处理 / 其它工具调用）

```bat
:: 解码文件（元数据路径）
CxQuickDecode.exe --decode "打码图.png" --password 你的密码 --out "还原.png"

:: 解码剪贴板
CxQuickDecode.exe --decode-clipboard --password 你的密码 --out "还原.png"

:: 没有元数据：手给区域 + 参数
CxQuickDecode.exe --decode "截图.png" --password 你的密码 --aabb "160,110,320,200" --unit 16 --soft 1 --out "还原.png"

:: 只给区域，unit/soft/偏移让它自己挑
CxQuickDecode.exe --decode "截图.png" --password 你的密码 --aabb "160,110,320,200" --out "还原.png"

:: 自检（对照参考向量，退出码 0 = 全过）
CxQuickDecode.exe --selftest "路径\vectors"
```

命令行模式的日志同时写到 exe 旁的 `cli.log`，并打印 `ok/unit/soft/偏移/块缝/耗时`。

## 五、自检（可复跑）

参考向量由 `ComfyUI-CX-ImageScramble/cx_core.py`（`image-crypto.js` 的 Python 等价移植）生成，C# 逐字节比对：

```
== 1) hash / perm 基准值 ========================================
== 2) PNG 编解码往返 ============================================
== 3) 元数据解码（图 + 密码）vs Python 参考 ====================
== 4) 手动区域路径（unit / soft 指定 + 自动择优）vs Python 参考 =
== 5) sortRegion（色块排序 flag bit1）vs JS 语义参考 ============
结果：86 通过 / 0 失败
```

覆盖：`hash`（含中文/emoji 密码）· `perm` · PNG 往返（1×1 到 256×200）· 10 张带元数据的打码图（1–3 区域，随机密码）· 4 组 unit/soft 手动路径（含自动择优是否选对）· 4 组色块排序（bl=1/9/12/40，`rbit` 变化）。所有比对都是 **maxΔ=0**。

真实样例（`samples/`）另跑了端到端：1280×800 大图、两区域、以及 unit=16/soft=1 的无元数据图，输出与参考 **maxΔ=0**。

## 六、已知边界（重要）

1. **必须无损**：元数据写在像素最低位，缩放 / JPEG 重压 / 任何调色都会抹掉它。截图请保证显示比例 100%（不要被浏览器缩放过）。
2. **网页端 JPEG 打码图（qv3<100）** 用的是 64px 边框 + J2 拍屏鲁棒码（RS(255,127) + 四角 Finder + 单应校正），**这一套没有移植**。这类图目前只能在网页端还原；PNG 打码图（含 8px 边框）完全支持。
3. **无元数据时必须给对区域**：区域要覆盖被打码的矩形并与 unit 网格对齐（差几像素由「偏移搜索」救，差太多就解不出）。截图时尽量贴着打码区域的边缘框。
4. **还原是「有损」的**：这是算法本身的性质（亮度被压到 [50,205] 再 ±40 扰动），平滑照片往返 PSNR ≈ 50–60 dB，大面积纯饱和色块会有可见偏差。C# 与网页端「自己加密再自己解密」的结果逐字节相同，所以这不是移植误差。
5. **区域数上限 12**（与网页端一致），超出部分网页端就不会写进元数据。
6. **诱饵模式（flag bit0）与色块排序（flag bit1）都已支持**；诱饵模式是「原始像素散在原图区 LSB」的路径，同样受「必须无损」约束。

## 八、实测反馈修复记录（v1.1）

用户实测报的三件事，逐条定位并修掉：

| 现象 | 根因 | 修法 |
|---|---|---|
| 点✕ / 截图报 `Only the invariant culture is supported in globalization-invariant mode` | csproj 开了 `InvariantGlobalization=true`，中文字体/资源取 culture（zh-CN / en-US）时直接抛 | 关掉（`false`），不再用 invariant 模式 |
| 剪贴板解码出来是噪声，但拖文件正常 | 旧实现走 WinForms 的 `Clipboard.GetDataObject()` → `Bitmap`，GDI+ 转换把边框 LSB 改掉了；浏览器明明也放了无损的 `PNG` 格式，却被跳过 | 改为**直读原生剪贴板**（`OpenClipboard/GetClipboardData`）：优先 `PNG` 原始字节（无损）→ `CF_DIBV5`/`CF_DIB` 原始 DIB → `CF_HDROP` 文件；只有全失败才退回 GDI+ |
| 截图解码报 `Type could not be marshaled because the length of an embedded array…` | `BitmapInfo.bmiColors` 的 `SizeConst` 写成了 1024（元素个数写成字节数），与实际 256 不符 | 改成 `SizeConst = 256`（256 个 RGBQUAD） |
| 点了「剪贴板解码」但没解出，密码框是空的 | 配置类用的是**字段**，`System.Text.Json` 默认不序列化字段 → 密码读了却永远是空 | 加 `JsonSerializerOptions { IncludeFields = true }` |
| 关掉窗口后进程直接没了（以为要重启） | `FormClosing` 只对 `UserClosing` 才 `Cancel`，`WM_CLOSE` 等其它 reason 会真关掉，消息循环结束 → 进程退出 | 除托盘「退出」外一律 `e.Cancel = true; Hide()` |
| 截图覆盖层一亮就自己消失 | 覆盖层在 `OnDeactivate` 里"失焦即取消"，而初始 `Canceled=true`，显示时焦点一抖就自杀 | 去掉失焦自动取消，只留 Esc / 右键 / 选区太小 |
| 覆盖层在多屏上位置/尺寸不对 | 覆盖层默认 `AutoScaleMode.Font`，按 DPI 把物理像素的 `Bounds` 又缩了一次 | 覆盖层用 `AutoScaleMode.None` + 显示时再钉一次 `Bounds` |
| 手动模式一次要 7.3 s | 无元数据时对 `unit²` 个偏移全网格搜索（848×1232 全图） | 改成两阶段（先 x 再 y）+ 提前收敛，实测 **7.3 s → 0.4 s** |
| 连续按热键第二次解出噪声 | 解码成功会把结果写回剪贴板，第二次读到的是自己上次的输出（没有元数据） | 记住上次输入/输出指纹：发现剪贴板是自己上次的结果，自动改用上次的原图重解 |

另外：单实例从命名 Mutex 换成 **exe 同目录独占文件锁**（进程被强杀也会释放；第二次启动会把已有窗口拉到前面），
状态栏对「元数据路径 / 按区域猜」分开提示，猜出来明显是噪声时标红。

### 仍然存在的限制

- **无元数据 + 多区域**：手动/截图路径只能按「一个矩形区域」逆变换，网页端存的多区域打码图必须先靠元数据（即原图文件）还原。
- **网页端 JPEG 路径**（qv3<100，64px 边框 + J2 鲁棒码）未移植。
- 剪贴板若只有位图（少数程序不给 PNG），LSB 可能已被转换，此时状态栏会明确提示改用原图文件。

补充（同一轮的顺带改进）：

- **全局热键带回退**：`Ctrl+Alt+Q/S/O` 被别的软件占用时，自动降级到 `Ctrl+Shift+Q/S/O`（再不行 `Ctrl+Alt+Shift+…`），
  状态栏会写清「哪个组合实际生效」，不会再只给一句"被占用"。
- 单实例换成独占文件锁后，进程被强杀也不会卡住下一次启动；第二次启动会把已有窗口拉到最前面。

## 九、实测第二轮（现场数据定位）

用户把图同时留在屏幕和剪贴板里，直接抓现场得到结论：

```
剪贴板格式（QQ「复制图片」）：
  FileDrop            -> D:\...\nt_data\Pic\2026-10\Ori\87b4f649...png   ← 无损原图
  DeviceIndependentBitmap / Format17 -> 848x1232 位图                     ← LSB 已被转换掉
  Bitmap / System.Drawing.Bitmap      -> 848x1232 32bppRgb                ← 同样已毁
```

- 那份 **PNG 原文件里元数据完好**：`848×1232`，8px 边框，1 个区域 `(248,536,288,160)`，密码一验就过 → 解出 `832×1216`。
- 剪贴板里的两份位图（DIB / DIBV5）里 `parseMeta` 全部为 `None` —— 说明 Windows 这边给的位图**已经不含最低位**了。

所以旧顺序（PNG 字节 → DIBV5 → DIB → 文件）必然踩到坏位图。现在改成：

**① 剪贴板文件列表（CF_HDROP，无损，最优先）→ ② PNG 原始字节 → ③ CF_DIBV5/CF_DIB → ④ GDI+ 兜底**

QQ / 微信 / 资源管理器「复制图片」基本都会带 FileDrop，所以这条路一改，剪贴板解码就是元数据路径。

### 截图为什么天生不稳（以及兜底）

屏幕上的图几乎总被缩放显示（窗口适配、看图器"适应窗口"、Windows 显示缩放 ≠100%）。
**只要不是 1:1，"像素最低位"就已经被插值抹掉了，任何工具都还原不了。** 实测抓屏后在整个图片区域
逐像素搜索也搜不到 `"CX"` 魔数 —— 证实屏幕上那份不是原始像素。

因此截图路径现在的行为：

1. 先按正常流程试（元数据 / 手动 unit·soft·偏移）；
2. 结果明显是噪声（块缝很大）时，**自动改用「上一次的原文件」**（剪贴板曾经给过的 FileDrop 路径，
   或此刻剪贴板里的文件）解一次 —— 状态栏会写「屏幕上的图不是 1:1 → 改用原文件 XXX」；
3. 没有原文件可退时，直接给结论：**截图救不回来，请复制原图或拖文件**，而不是丢一张噪声给用户。

想让截图真的可用，只有一个前提：**看图器 1:1（100%）显示 + Windows 显示缩放 100%**。

### 实测数字（本轮现场）

| 路径 | 结果 |
|---|---|
| 剪贴板（自动走 FileDrop 原文件） | ✔ 832×1216 · **20 ms** · 元数据路径 1 个区域 |
| 截图（检测到缩放 → 用原文件） | ✔ 832×1216 · **5 ms** · 元数据路径 1 个区域 |
| 直接 `--decode <原文件>` | ✔ 832×1216 · 13 ms |
| 参考向量自检 | 86 通过 / 0 失败 |

## 十、交互改版（v1.2）

### 1. 结果浮层（窗口尺寸不再变）

解码结果不再塞进悬浮窗，而是弹一个**浮层**贴在悬浮窗/悬浮球的上方（上方空间不够就下方），
按图片比例缩放到最大 420×320，底部一行信息（尺寸 · 耗时 · 元数据/猜测）。

- 停留 `PopupSeconds`（默认 3.5s，设置里可改 0.8–30s）后淡出；**鼠标停在浮层上不消失**，移开继续计时。
- 点浮层 = 打开完整预览（可 1:1 / 适应 / 另存为）。
- 悬浮窗固定 `420×150`，只保留标题 / 密码 / 三个按钮 / 一行状态，永远不会被结果撑大。

### 2. 悬浮球（缩略模式）

标题栏 `◎` 进入；托盘菜单「悬浮球模式」也能进。

| 操作 | 行为 |
|---|---|
| 左键单击 | 剪贴板解码 |
| 左键拖动 | 移动球（位置会记住） |
| 右键单击 | 截图解码（等 360 ms 确认没有第二下） |
| **右键双击** | 退出球模式，回到悬浮窗 |
| 拖图片进球 | 解码该文件 |

- 尺寸 48–140 px、样式（图标 / 文字 CX）、不透明度 40–100%，都在设置里调，改完立刻生效。
- 结果浮层同样贴在球的上方/下方。

### 3. 设置界面

托盘右键 →「设置…」，或命令行 `CxQuickDecode.exe --settings`。

- **快捷键**：三行各一个「录制」按钮，点完直接按组合键（Esc 取消）。支持 Ctrl / Alt / Shift 任意组合；
  注册失败会自动退到 Ctrl+Shift、Ctrl+Alt+Shift，并在状态栏写清实际生效的组合。
- **结果浮层**：开关、停留秒数、是否自动复制结果到剪贴板。
- **悬浮球**：直径、样式、不透明度。
- **性能**：空闲自动降耗开关与阈值、窗口置顶。
- **配置**：显示当前配置文件路径，可一键打开所在文件夹、恢复默认。

```
%USERPROFILE%\Documents\CxQuickDecode\cxq.config.json
%USERPROFILE%\Documents\CxQuickDecode\cxq.log          ← 排障日志（可删）
```

- 想保持 U 盘便携：在 exe 同目录放一个空文件 `cxq.portable`，配置就写回 exe 旁边。
- 首次运行会把旧位置（exe 同目录）的 `cxq.config.json` 自动迁移过来，旧文件改名为 `.bak`。

## 十一、图库 / 悬浮栏入口 / 悬浮球自定义外观（v1.3）

### 1. 图库（本次运行解出的全部图片）

托盘右键 →「图库…」，或点悬浮栏右下角的 **图库** 按钮。

- 内存图库，只保留**本次运行**（重启即清空），最多 60 张，最新的排最前。
- 每张存 PNG 字节 + 128px 缩略图（不存整张 Rgba，避免大图把内存吃爆）。
- 双击缩略图 → 完整预览；右键 → 打开预览 / 另存为 / 复制到剪贴板 / 从图库移除；
  底部还有「全部另存…」「清空」。
- 解码成功时自动入库（无元数据的"按区域猜"也入库，方便对比）。

### 2. 悬浮栏上的入口按钮

展开态悬浮窗的状态行右侧新增两个小按钮：**图库**、**设置**（原来只能从托盘进）。
状态行文字自动省略（`AutoEllipsis`），不会把窗口撑大。

### 3. 悬浮球自定义外观

设置 → 悬浮球（缩略模式外观）：

| 项 | 说明 |
|---|---|
| 直径 | 48–160 px |
| 内容 | 默认图标 / 文字 / 自定义图片 |
| 文本 | 任意文字（默认 `CX`）+ 缩放 0.4–1.6 + 旋转 −180…180（字号自适应，文字过长自动缩） |
| 图片 | 支持 **png / jpg / bmp / gif / svg**，可设缩放 0.3–1.6 与旋转 |
| 背景 | 任意颜色 + 背景不透明度 0–100% |
| 整体不透明度 | 球（含内容）整体 20–100% |

绘制细节（对应"缩小不要锯齿"的要求）：

- **SVG 走矢量**：用 `Svg` 库按目标尺寸直接栅格化（`doc.Draw(w, h)`），不是先渲染再缩，所以小尺寸依然干净；
  按 viewBox 等比适配后居中到正方形画布。
- **位图**用 `HighQualityBicubic` + `PixelOffsetMode.HighQuality` + `ImageAttributes.SetWrapMode(TileFlipXY)`（缩小边缘不发黑/不出半像素锯齿），
  并按"内容目标尺寸"预渲染缓存，只在缩放/旋转/换图时重建，重绘时不缩放原图。
- **描边**：静默态完全不画边；只在**拖动时**出现白色描边 + 淡蓝辉光（松手即消失）。
- 内容位图按 `内容|文本|路径|尺寸|缩放` 做 key 缓存，避免每帧重算。

### 4. 多屏修正

图库 / 设置 / 预览窗原来用 `CenterScreen`，在无边框 + 高 DPI 下算出的坐标会落到**另一块屏**（实测跑到 x=-920）。
现在统一改为 **在「鼠标所在屏幕」的工作区居中**（`Screen.FromPoint(Cursor.Position)`），
点哪个屏上的按钮就在哪个屏弹出。

另外顺手修了设置里「直径」数值框被文字块压住、只显示一位数的问题（输入框加宽 + 标签收窄）。

## 十二、操作与手势改成可配置表（v1.4）

按参考图（Snipaste 的「贴图操作」）把鼠标操作做成一张可编辑表：

```
操作                修饰键   第二键   鼠标动作
剪贴板解码          无       无       左键单击
截图解码            Ctrl     无       右键单击
打开托盘菜单        无       无       右键单击
退出悬浮球模式      无       无       右键双击
打开图库            Shift    无       左键单击
打开设置            无       无       中键单击
* 如有冲突，由上至下优先匹配。左键拖动仍然是移动悬浮球（不会触发动作）。
```

- 入口：设置 → 悬浮球 → **操作与手势…**；或命令行 `CxQuickDecode.exe --actions`。
- **右键 = 弹出托盘图标的右键菜单**；**Ctrl+右键 = 截图解码**（就是你说的默认语义）。
- 悬浮窗（展开态）上右键同样弹托盘菜单；左键拖动窗口不变。

实现要点：

- **手势识别**：所有按键统一走"按下 → 320 ms 判定"，同键二次按下在 320 ms 内算双击；
  这样"右键单击 = 菜单"不会把"右键双击 = 退出球"吃掉（菜单弹出前就把双击判完了）。
- **修饰键**读 `GetAsyncKeyState`（物理按键，无焦点也准）+ `Control.ModifierKeys`（有焦点时最准）取并集，
  并按 `Ctrl → Shift → Alt` 归一化顺序比较，所以表里写 `Shift+Ctrl` 和 `Ctrl+Shift` 等价。
- 左键按下后移动超过 4 px 即视为**拖动**：取消待判定手势、显示拖动描边、只移动球。
- 匹配是**顺序优先**：同一手势被多行命中时，用最上面那行（所以"无修饰右键"能稳定命中菜单）。
- 配置存 `OrbActions` 数组，缺省自动补默认表；旧配置没有这一项也能直接用。

验证：把「截图解码」临时改成「中键单击」后，用 `WM_MBUTTONDOWN` 触发，日志走到 `orb action: shot` → 表匹配与动作分发正确；
右键双击也实测回到 420×150 窗口。`Ctrl+右键` 的 Ctrl 状态在自动化注入里读不到（UIPI/会话限制），已用双来源读取兜住，真实按键必触发。
